Change vs. the earlier 38/42:
  The emitter previously emitted a column-level `unique` test on each satellite /
  eff-sat hash key. A satellite historises each hash key over time, so its grain is the
  composite (hash key + load date) — the hash key alone repeats across versions, so
  `unique` on it is wrong by Data Vault design and failed (4 failing tests).

  Fix (dv_components emitter): satellites/eff-sats now emit `not_null` on the hash key
  and a model-level `dbt_utils.unique_combination_of_columns` on (hash key + load date).
  Hubs and links are unchanged (their hash key IS unique, so they keep `unique`).

  Result: the 4 spurious failures are gone and uniqueness is asserted on the correct
  grain -> 42/42.
